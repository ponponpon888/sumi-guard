# 管理下PowerShell評価・保存・表示 統合デモ記録

## 対象範囲

新規の `Invoke-SumiGuardManagedAssessmentStoreDemo.ps1` と
`Invoke-ManagedAssessmentStoreDemoTests.ps1` だけで、既存の管理下PowerShellランナー、
CommandAssessment、AssessmentStore、評価表示CLIを接続した。既存ファイル、既存フック、
ReadOnly版、`.demo-data`は変更していない。

## 静的確認

- 新規デモおよび新規試験はUTF-8 BOM付き。
- Windows PowerShell 5.1の構文解析エラーは両方とも0件。
- 評価、保存、実行、表示は別々の状態項目として返す。
- 合成評価は `SYNTHETIC_TEST` とし、関連 `execution_id` を保存しない。表示は「試験データ」および未実行状態を明示する。
- 管理下実行として保存する場合だけ、実際に起動した固定コマンド用の関連 `execution_id` を使用する。
- 保存失敗は評価状態を変更しない。本文、断片、URL、パス、秘密値、生ストリーム、生例外は保存・表示しない。

確認内容は、3ルールの検知例、4評価状態、部分評価、保存失敗と評価結果の分離、使い捨てストアへの保存・読戻し、日本語表示、非漏えい、乾式の「試験データ／未実行」表示である。入力コマンドは文字列として評価しただけで実行していない。

## 管理下固定コマンドの一回確認

合成統合試験の合格後、明示スイッチを指定して固定無害コマンドのデモを一回だけ要求した。

| 項目 | 結果 |
|---|---|
| デモランナー終了コード | 1 |
| デモランナー起動回数 | 1 |
| 管理下子プロセス起動回数 | 0 |
| 評価状態 | `EVALUATION_FAILED` |
| 評価保存 | 未実施 |
| 日本語表示確認 | 未実施 |

このため、管理下固定コマンドについて評価→保存→表示までの実行時成功は確認できていない。生エラー、本文、生標準出力、生標準エラーは記録しない。PC全体の監視、Codex実フックでの検知開始、常駐化、外部通知、遮断、隔離を意味しない。

## 変数衝突の原因と修正

失敗後の静的調査で、表示CLIをドットソースする際の `StorePath` パラメーターが、統合デモの同名入力を一時ディレクトリ値で上書きすることを確認した。また既存管理下ランナーにも同名の `RunFixedCommand` パラメーターがある。両方をドットソース前に専用のスクリプト変数へ退避し、エントリーポイントでは退避値だけを使うよう修正した。

評価未到達の統合失敗は、評価器の `EVALUATION_FAILED` として扱わない。`assessment_obtained=false` と評価状態なしを返し、固定の統合状態と段階を別項目で保持する。評価取得後の保存・表示失敗では、取得済みの評価状態と固定理由コードを保持する。

## 出力ストリーム分離の修正

統合関数が表示行を成功ストリームへ流したため、エントリーポイントでは表示行と構造化レポートが混在していた。表示行はメモリ内で捕捉し、固定ラベルの確認Booleanだけを構造化レポートへ含めるよう修正した。保存後は同じ評価IDの読戻しを別段階で確認し、評価、保存、読戻し、表示、集約を分離して返す。

新規回帰試験は4件すべて合格、終了コード0、管理下子プロセス起動0件だった。修正後のWindows PowerShell 5.1乾式入口は終了コード0、構造化レポート1件、評価・保存・読戻し・表示・固定ラベル・集約すべて成功、実コマンド起動0件だった。使い捨てストアは清掃済みである。過去の `ATOMIC_WRITE_FAILED` の原因は未確定のままとする。

## 完成確認と評価専用CLI

管理下固定無害コマンドの確認は1回実行し、終了コード0、構造化レポート1件、評価・保存・同一評価ID読戻し・表示・集約すべて成功した。子プロセスは1回起動、終了コード0、タイムアウトなし、固定出力一致だった。保存記録の起点は `MANAGED_EXECUTION`、保存済み関連execution_idは実行側IDと一致した（ID値は記録しない）。使い捨てストアは清掃済みである。

`tools\Test-SumiGuardPowerShellCommand.ps1` は本文を実行・保存しない評価専用入口である。明示したWindows PowerShell 5.1ソースとして解析するが、実行インタープリターを確認したとは扱わない。新規CLI試験は5件すべて合格した。過去の `ATOMIC_WRITE_FAILED` の原因は未確定のままとする。

日本語警告表示を追加し、検知時は固定の注意見出し、ルールID、重大度、固定理由を表示する。非検知は安全と表示せず、評価不能・部分評価も固定文で区別する。日本語警告CLI試験は7件すべて合格し、入力実行・保存・ネットワーク・子プロセス起動はいずれも0件だった。

## 警告CLI表示整理と失敗種別の回帰確認

評価全体の固定理由コードが空の場合は `理由: なし` を出力しないよう整理した。検知findingのルールID、重大度、固定の日本語説明は維持した。評価不能、部分評価、評価器が返す `EVALUATION_FAILED` は固定理由を表示し、CLI内部失敗は理由や例外詳細を表示せず固定の「評価処理失敗」と終了コード `3` を返す。評価器が返す `EVALUATION_FAILED` は終了コード `2` として別に扱う。

Windows PowerShell 5.1で新規CLI試験10件を実行し、10件合格・終了コード0だった。対象は3ルールの検知、非検知、評価不能、コメント・引用文字列と秘密を模した値の非漏えい、部分評価、評価器失敗、CLI内部失敗、未知理由コードである。入力実行、入力保存、ネットワーク、子プロセス起動はいずれも0件だった。
